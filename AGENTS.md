# Clipforge
Standalone English-language podcast/talking-head clipping SaaS. Never touch BrainrotAI's data, cloud resources, or repository. Never deploy or create live infrastructure without explicit approval. Always review Alchemy plans. Read `node_modules/effect/AGENTS.md` before writing Effect code; consult pinned Alchemy v2 source and official docs before changing resource declarations. Keep secrets out of source, logs and committed config. Tenant-scope every asset and state mutation. Schema-validate external input, use idempotency for jobs and billing. Render/media processing belongs in Containers, not Workers. Do not treat passing local fake-provider tests as verification of live provider integration.

## Autonomous PR workflow
One writer per branch/worktree. Keep `master` clean; make independently reviewable PRs in feature worktrees. Do not remove a worktree while it contains unmerged work or private evidence. For a task, read the feature map in `.agents/skills/clipforge-verify/references/feature-map.md`, reproduce the issue, add a regression, implement, run the verification skill, inspect the resulting UI/artifact, and review the **exact commit SHA**. Fix substantive review issues and repeat until checks pass; do not stop at a first slice or churn on speculative polish. A reviewer must not silently review an outdated SHA. Promote recurring findings into executable checks.

Unattended: local edits/tests/builds, worktrees, feature-branch pushes, and draft PRs are fine. No DNS, cloud mutation, staging deploy, live email, Stripe checkout, paid inference, production release, or secret exfiltration without explicit prior authorization for that operation. Do not ask to decide reversible internal implementation details; choose a sensible approach and document trade-offs. If blocked by a real external authorization, continue other useful local work and open a draft PR with a precise blocker and proof of what did pass. A PR is shippable **within its stated verification scope** when SHA-pinned checks and CI pass, relevant regression and user-facing behavior are checked, limitations are explicit, and the diff contains no credentials/fixtures. Offline shippable does not imply live-release-ready. Read `.agents/skills/clipforge-verify/SKILL.md` for the reproducible command and evidence contract.
