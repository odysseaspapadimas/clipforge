# Clipforge

Independent SaaS for turning customer-uploaded English podcasts and talking-head interviews into editable 9:16 shorts. BrainrotAI was inspected read-only for rendering ideas; the two products are not coupled and no BrainrotAI code is imported.

## Real product path

1. Better Auth creates an account with **real verification mail** (Cloudflare Email Sending when a sender domain is onboarded; Resend is a fallback). Alchemy's **built-in Stripe provider** provisions a TEST-mode product, monthly price, restricted Checkout/Portal bindings and verified webhooks. Only a paid subscription invoice grants source minutes. A source reserves `ceil(duration / 60s)` minutes; terminal ingestion failures release them.
2. Customer uploads MP4/MOV/WebM (under 5 GiB and 2 hours), in resumable 32 MiB Worker-proxied R2 multipart parts. The private Container probes the source and extracts 60-second, ~0.5 MiB mono audio segments. Worker streams and validates the segment manifest, storing each segment privately in R2.
3. By default, Cloudflare Workers AI's **`@cf/deepgram/nova-3`** transcribes each segment through the native binding, with word-level timing and chunk-local diarization. An explicit, separately keyed `deepgram` backend remains available for guarded staging fallback; it transcribes the same short chunks and is never activated automatically after a Cloudflare failure. Workflows checkpoint each segment result to R2, normalize timestamps, store one D1 row per timed word, suggest clips using transcript pause/context windows and optionally rank suggestions with **`@cf/meta/llama-3.3-70b-instruct-fp8-fast`**. Inference is real when deployed; no inference has been invoked by local tests. A per-chunk progress indicator updates in the editor.
4. Customers review suggestions, adjust boundaries, manual focal-point crop, title and word captions. The same FFmpeg Container produces H.264/AAC vertical MP4 with burned-in captions, stored privately and served by authenticated ranged playback/download. Face tracking and speaker-to-face association are deliberately not advertised.

TanStack Start/React + Better Auth on Workers; D1 for auth, projects, transcript, jobs and period-scoped credit ledger; R2 for private media; Workflows for durable background steps; a D1-leased two-slot global scheduler and Bun/FFmpeg in Cloudflare Containers; Alchemy v2 for resource definitions and built-in Stripe. The provisional plan is **$29/month for 120 source minutes** and up to 20 exports/source. Media expires after 90 days. Provider costs and commercial terms need confirmation before public paid release.

## Verification status

`bun run typecheck`, `bun test test renderer`, `bun run build`, `bun run test:e2e`. The browser test exercises auth, upload, editing, real FFmpeg export and tenant isolation locally, **but its transcription and billing adapters are explicitly offline fakes**. The native Workers AI adapter, explicit Deepgram fallback, schema and chunk-merging code have offline contract tests. The actual Container image was built locally: it extracted three segments from a 126-second recording and **120 bounded segments from a 7,199-second recording**. Neither run invoked a speech model. None of this is evidence of a live deployed customer journey. Staging deployment and inference remain gated by TEST Stripe credentials, verified outbound email, and Cloudflare identity/plan approval. A separate **$3 Clipforge STAGING model-inference allowance** is approved; code currently hard-limits staging to 10 total source minutes (~$0.052 published Nova transcription rate) and stops before inference when that pool is exhausted. Actual model billing must be checked after the first very short recording. No cloud infrastructure, Stripe catalog or paid inference was provisioned by this checkout.

See [staging operations and hard gates](docs/operations.md). This stack refuses to operate outside the `staging` stage and refuses non-TEST Stripe keys. Never run `alchemy dev`, `plan` or `deploy` assuming those are local: they can contact and create real resources. Production merge/deploy is not authorized.
